Install

One dependency. Every component reads the same tokens, so theming lives in one place.

flutter pub add prism_kit

// One import gives you everything.
import 'package:prism_kit/prism.dart';

// Register a look once, at the root.
MaterialApp(
  theme: prismTheme(seed: brandPurple),
  darkTheme: prismTheme(seed: brandPurple, brightness: Brightness.dark),
  home: const HomePage(),
);

What makes it different

Three things that are easy to claim and harder to deliver. All three are covered by tests you can read.

A design system, not a bundle

Every one of the 51 components reads PrismTokens and PrismColors. Tests install deliberately unusual tokens and assert the components adopt them, so a hard-coded radius or duration fails CI.

Accessible by default

Live regions for state you did not trigger, decorative content hidden from screen readers, minimum touch targets, sortable headers that announce their direction, and reduced motion honoured everywhere.

Adaptive, not just responsive

Tables become labelled cards on a phone. Tabs scroll instead of clipping. The stepper collapses to a step counter. Compact below 600 px, expanded above 840 px, one widget throughout.

Zero lock-in

No database, backend or cloud dependency. The AI client and the updater are the only networked pieces, and you own the endpoints.

Verified, not vibes

The semantic palette is checked against WCAG AA across ten brand seeds in both brightnesses, and a 184-case matrix pumps every component at 320 px and 1600 px in LTR and RTL.

Testing helpers included

prismTestApp configures the tokens, a real viewport, brightness, direction and reduced motion — because a zero-size viewport makes adaptive tests silently assert nothing.

durationFast 120 ms · durationMedium 240 ms · durationSlow 420 ms

Durations collapse to zero when the platform asks for reduced motion. Controls default to 44 px tall.

Semantic roles

success and warning use fixed, tested colours so they never collapse into a green or amber brand colour. error and info come from your own ColorScheme.

success · #1B7A4B on #C9F2DC warning · #8A5A00 on #FFE7B8

Built to be read

The source is short and documented, with no clever indirection. If you want to know how something works, read it.

  • Strict analysis. strict-casts, strict-inference and strict-raw-types, reporting zero issues.
  • Every animated component takes its duration from the platform's reduce-motion setting.
  • Style classes resolve against the theme. Unset fields stay nullable and are filled in one resolve(context) call.
  • Documented trade-offs. Where something is a heuristic — token estimation, deletion detection — the docs say so.
  • 620 test cases written across unit, widget and matrix suites. Read them.
